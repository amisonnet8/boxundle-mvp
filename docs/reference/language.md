# Boxundle 言語リファレンス

> 版：v0.3（2026-10-25）

Boxundle の箱の形式（`.bx`）の定義。字句・文法・意味・検証・エラー・値の受け渡しを定める。

- 標準の箱：[std.md](std.md)
- コマンド：[cli.md](cli.md)
- 例：[../examples/](../examples/)

この文書は、Boxundle を初めて使う AI に渡す言語仕様の元にもなる。

---

## 1. 用語

| 用語 | 定義 |
|---|---|
| モジュール | 1つの `.bx` ファイル。型定義と箱を含む |
| 箱（box） | 入力ポート・出力ポート・権限・テスト（＝外側）と、本体（＝内側）を持つ処理単位 |
| 外側 | `in` / `out` / `perm` / `test`。人間が理解・承認する部分 |
| 内側（本体） | `body`。AIが読み書きする部分 |
| 標準の箱 | `boxundle` に組み込まれた、本体を持たない箱。外側の宣言（`.bx`）と、Goによる実装からなる。名前は `std.` で始まる。宣言なしで常に使える |
| 作用のある箱 | `perm none` 以外の標準の箱。外部の世界（時刻・乱数・環境変数・ファイル・ネットワーク）に触れる |
| ノード | 本体内の1つの処理。固定のIDを持つ |
| ポート | 箱の入力・出力。`$名前` で参照する |
| 束縛子（binder） | `map` などのブロック内で要素を指す名前。`$名前` で参照する |
| ブロック | `{ ... }` で囲まれたノード列。値を持つか、出力を確定させる |

## 2. 字句

- **文字コード**：ソースはUTF-8。不正なバイト列は `BX001`
- **空白**：スペース、タブ、改行（LF・CRLF）はすべて区切りとして同一に扱う
- **識別子 `NAME`**：Unicodeの XID_Start（または `_`）で始まり XID_Continue が続く（日本語可）。キーワードは不可
- **修飾名 `QNAME`**：`NAME { "." NAME }`（例：`std.text.split`、`fs.read`）
- **ノードID `NODEID`**：`#` に続いて、ドット区切りの正の整数列（例：`#4`、`#4.1.2`）。各整数に先頭の0は不可
- **ポート・束縛子 `DOLLAR`**：`$` に続いて `NAME`（例：`$order`、`$e`）
- **整数 `INT`**：`-?[0-9]+`
- **小数 `DEC`**：`-?[0-9]+\.[0-9]+`
- **文字列 `STRING`**：`"` で囲む。エスケープは `\"` `\\` `\n` `\t` `\uXXXX`。生の改行は含められない
- **ラベル `LABEL`**：`@` に続く `STRING`（例：`@"在庫が足りない明細"`）
- **キーワード**：`module externs extern type box in out perm none test given expect stub body emit impl as true false`
- **組み込み型名**：`Int Dec Bool Str`

演算名（`map`、`route` など）はキーワードではなく識別子として字句解析し、ノードの位置で照合する。

### 2.1 参照の書き方

| 参照 | 書き方 | 例 |
|---|---|---|
| ノード | `#` + 数字列 | `#4.1` |
| ポート・束縛子 | `$` + 名前 | `$order` |
| フィールドアクセス | 参照の後ろに `.名前`（名前は数字で始まらない） | `$order.lines`、`#3.result`、`#4.1.total` |

`#4.1.total` は「ノード `#4.1` の `total` フィールド」と解釈する。ドットの後が数字だけならノードIDの続き、名前ならフィールド。

## 3. 文法（EBNF）

利用者が書く `.bx` ファイル（モジュール）の文法。標準の箱の宣言の文法は [std.md](std.md) にある。

```ebnf
module      = "module" NAME { item } ;
item        = typedef | box ;

typedef     = "type" NAME "=" type ;
type        = tatom { "|" tatom } ;             (* | は名前付きレコード型どうしのみ *)
tatom       = "Int" | "Dec" | "Bool" | "Str" | QNAME
            | "[" type "]"                      (* リスト *)
            | "{" type "->" type "}"            (* マップ *)
            | "{" field { "," field } "}" ;     (* レコード *)
field       = NAME ":" type ;

box         = "box" NAME [ LABEL ] "{"
                { port } perm { test } body
              "}" ;
port        = ( "in" | "out" ) DOLLAR ":" type ;
perm        = "perm" ( "none" | QNAME { "," QNAME } ) ;
test        = "test" STRING "{" { stub } "given" record_lit "expect" record_lit "}" ;
stub        = "stub" QNAME record_lit ;          (* 呼び出し先の箱の出力を固定する *)
body        = "body" block ;

block       = "{" { stmt } "}" ;
stmt        = node | emit ;
node        = NODEID op { arg } [ binder ] [ blocks ] [ LABEL ]
            | NODEID "call" QNAME call_args [ LABEL ] ;
call_args   = "{" [ farg { "," farg } ] "}" ;
emit        = "emit" DOLLAR arg ;
binder      = "as" DOLLAR
            | "as" "(" DOLLAR "," DOLLAR ")" ;
blocks      = block
            | "{" branch { branch } "}" ;       (* route / match のみ *)
branch      = ( "true" | "false" ) block
            | QNAME DOLLAR block ;              (* match：型名 束縛子 ブロック *)

arg         = ref | literal | construct | "(" literal ":" type ")" ;
ref         = ( NODEID | DOLLAR ) { "." NAME } ;
construct   = QNAME "{" [ farg { "," farg } ] "}"  (* 名前付きレコードの構築 *)
            | "{" farg { "," farg } "}"            (* 無名レコード *)
            | "[" [ arg { "," arg } ] "]"          (* リスト *)
            | "{" marg { "," marg } "}"            (* マップ *)
            | "{" "->" "}" ;                       (* 空マップ *)
farg        = NAME ":" arg ;
marg        = arg "->" arg ;

literal     = INT | DEC | STRING | "true" | "false" ;
record_lit  = "{" [ farg { "," farg } ] "}" ;      (* キーはポート名（$なし）。値はリテラルと構築のみで、参照は不可 *)
```

補足：

- `op` は §4.3 の演算名のいずれか。`route` / `match` のときだけブロックが分岐形式になる。パーサは演算名を見て分岐形式かどうかを決める
- 空リスト `[]` と空マップ `{->}` は、期待される型が文脈から決まる場所（`emit` の引数、`call` の引数、テストの値）以外では `([] : [Int])` のように型注釈が必要
- 利用者のファイルが `externs` で始まっていたら、またはモジュール内に `extern` があれば `BX070`（`externs` / `extern` は標準の箱の宣言専用）
- モジュールで定義する型・箱の名前は `std` で始めてはならない（`BX005`）

## 4. 意味

### 4.1 型

| 型 | 説明 |
|---|---|
| `Int` | 任意精度整数 |
| `Dec` | 10進小数（有効桁28、丸めは HALF_EVEN。Pythonの `decimal` の既定と同じ挙動） |
| `Bool` | 真偽値 |
| `Str` | Unicode文字列。長さや位置は**コードポイント単位** |
| `[T]` | リスト |
| `{K -> V}` | マップ。キー型は `Int` `Str` `Bool` のみ。走査順は常にキーの昇順（`false < true`、文字列はコードポイント列の辞書順） |
| `{f: T, ...}` | レコード（構造的） |
| `type N = {...}` | 名前付きレコード型。タグ `N` を持つ |
| `A \| B` | 名前付きレコード型の和（タグ付きユニオン） |

- `Int` と `Dec` は自動変換しない。`to_dec` を使う
- 名前付きレコード `A` の値は、`A` を含むユニオン型の位置にそのまま渡せる（自動注入）
- 等値比較は構造的（レコードはタグとフィールド、リストは順序込み、マップはキーと値）。`Dec` は数値として比較する（`1.0` と `1.00` は等しい）
- 再帰型は禁止（型定義の循環は検証エラー）
- 標準の箱の宣言で定義した型（`std.` 付き）は、モジュールから名前で参照できる

### 4.2 スコープとID

1. 箱の中のノードIDは、**箱全体で一意**
2. ブロック内のノードのIDは、そのブロックを持つノードのIDを接頭辞に持ち、1段だけ深い（`#4` のブロック内は `#4.1`、`#4.7` など）。`route` / `match` の全分岐はまとめて1つの親の子として扱い、分岐をまたいでも一意
3. IDの数字は連番でなくてよい（途中への挿入を可能にするため）。**IDは識別子であり、位置ではない。** 順序はテキスト上の位置で決まる
4. ノードが参照できるもの：
   - 同じブロック内で、テキスト上それより前にあるノード
   - 祖先ブロックで、そのブロックを持つノードより前にあるノード
   - 入力ポート
   - スコープ内の束縛子
5. 出力ポートは参照できない（`emit` の対象としてのみ書ける）
6. ポート名と束縛子名は、スコープ内で重複してはならない（シャドーイング禁止）。兄弟ブロックで同じ束縛子名を使うのは可

### 4.3 組み込み演算

`a, b` は引数、`{blk}` はブロック、`$e` は束縛子を表す。ブロックの値は、そのブロックの**最後のノードの値**。

**基本**

| 演算 | 引数 | 結果 | 説明 |
|---|---|---|---|
| `val` | a: T | T | aをそのまま値にする（ブロックの値を参照やリテラルで終えたいとき用） |

**算術**

| 演算 | 引数 | 結果 |
|---|---|---|
| `add` `sub` `mul` | (Int, Int) / (Dec, Dec) | 同じ型 |
| `div` | (Dec, Dec) | Dec |
| `idiv` `mod` | (Int, Int) | Int（床除算。`mod` の符号は除数と同じ） |
| `neg` `abs` | Int / Dec | 同じ型 |
| `min` `max` | (Int, Int) / (Dec, Dec) | 同じ型 |
| `to_dec` | Int | Dec |
| `floor` | Dec | Int |
| `round` | (Dec, places: Int) | Dec（HALF_EVEN。placesは0以上） |
| `to_str` | Int / Dec / Bool | Str（Decは指数表記を使わない。Boolは `true` / `false`） |

ゼロ除算は実行時エラー `BX-RUN-001`。`round` の places が負なら `BX-RUN-002`。

**比較・論理**

| 演算 | 引数 | 結果 |
|---|---|---|
| `eq` `ne` | (T, T) | Bool |
| `lt` `le` `gt` `ge` | (Int, Int) / (Dec, Dec) / (Str, Str) | Bool |
| `and` `or` | (Bool, Bool) | Bool（両方の引数は評価済みの値。短絡評価の区別はない） |
| `not` | Bool | Bool |

**文字列・リスト・マップ**

| 演算 | 引数 | 結果 |
|---|---|---|
| `concat` | (Str, Str) / ([T], [T]) | 同じ型 |
| `len` | Str / [T] / {K->V} | Int（Strはコードポイント数） |
| `empty` | Str / [T] / {K->V} | Bool |
| `sum` | [Int] / [Dec] | Int / Dec（空なら0） |
| `reverse` | [T] | [T] |
| `take` `drop` | ([T], n: Int) | [T]（nが負なら0、長さを超えたら長さとして扱う） |
| `distinct` | [T] | [T]（最初の出現を残す） |
| `range` | n: Int | [Int]（0〜n-1。nが0以下なら空。nが1,000,000を超えたら `BX-RUN-003`） |
| `lookup` | (m: {K->V}, k: K, default: V) | V（キーがなければdefault） |
| `has` | (m: {K->V}, k: K) | Bool |
| `set` | (m: {K->V}, k: K, v: V) | {K->V}（新しいマップ） |
| `remove` | (m: {K->V}, k: K) | {K->V} |
| `keys` | {K->V} | [K]（昇順） |
| `values` | {K->V} | [V]（キー昇順） |

**レコード**

| 演算 | 書き方 | 結果 |
|---|---|---|
| フィールド参照 | `$r.f` / `#3.f` | フィールドの型 |
| `with` | `#n with r {f: v, ...}` | rと同じ型で、指定フィールドだけ置き換えた新しいレコード |

**繰り返し（すべて有限の集まりへの操作）**

| 演算 | 書き方 | 結果 |
|---|---|---|
| `map` | `#n map xs as $e {blk}` | [U]（Uはブロックの値の型） |
| `flat_map` | `#n flat_map xs as $e {blk:[U]}` | [U] |
| `filter` | `#n filter xs as $e {blk:Bool}` | [T] |
| `any` `all` | `#n any xs as $e {blk:Bool}` | Bool（空なら `any` は false、`all` は true） |
| `fold` | `#n fold xs init as ($acc, $e) {blk:A}` | A（initの型と、ブロックの値の型が一致すること） |
| `sort_by` | `#n sort_by xs as $e {blk:K}` | [T]（KはInt/Dec/Str。安定ソート・昇順） |
| `group_by` | `#n group_by xs as $e {blk:K}` | {K -> [T]}（KはInt/Str/Bool。各グループ内は元の順） |

**分岐**

| 演算 | 書き方 | 説明 |
|---|---|---|
| `route` | `#n route cond { true {blk} false {blk} }` | condはBool。両分岐必須 |
| `match` | `#n match v { A $a {blk} B $b {blk} }` | vはユニオン型。全タグを網羅すること。束縛子の型はそのタグのレコード型 |

分岐は2種類のどちらかでなければならない（混在は `BX032`）。

- **値の分岐**：すべての分岐ブロックが `emit` を含まず、値で終わる。分岐ノードの値は選ばれた分岐の値。全分岐の値の型が一致すること（ユニオンへの自動注入は、期待される型が分かる場合のみ）
- **出口の分岐**：すべての分岐ブロックが `emit` で終わる。分岐ノードは値を持たず、本体または外側の出口の分岐ブロックの**最後のノード**でなければならない（`BX031`）

**他の箱の利用（入れ子）**

| 演算 | 書き方 | 結果 |
|---|---|---|
| `call` | `#n call QNAME {port: arg, ...}` | `{出力ポート名: 値, ...}` のレコード |

- 呼び出せるのは、同じモジュール内の箱と、標準の箱
- 全入力ポートを過不足なく渡すこと。入力のない箱は `{}`
- 箱の呼び出しの循環（直接・間接の再帰）は禁止（`BX041`）

### 4.4 出力（emit）

- `emit $port arg` は出力ポートに値を確定させる
- 本体のどの実行経路でも、**各出力ポートにちょうど1回** `emit` されること（`BX030`）
- `emit` が書けるのは本体の直下、または出口の分岐ブロックの中のみ。`map` などのブロック内には書けない

### 4.5 評価

- 本体は純粋・正格・決定的。外への作用は作用のある標準の箱の中でのみ起きる
- 評価順序は依存関係だけで決まり、利用者からは観測できない。インタプリタはテキスト順に評価してよい（参照は常に前方のみなので正しく動く）
- `route` / `match` は選ばれなかった分岐を評価しない（その中の箱も呼ばれない）
- **実装上の注意**：マップの値はキーを整列した状態で保持するか、走査のたびに整列する。Goの `map` の走査順を結果に漏らしてはならない
- 箱の呼び出しの深さは、循環禁止により有限。ただしインタプリタは深さ1,000を超えたら `BX-RUN-003` で止める（防御）

### 4.6 権限

**権限名**

| 権限 | 意味 |
|---|---|
| `net` | ネットワークへのアクセス |
| `fs.read` | ファイルの読み込み |
| `fs.write` | ファイルの書き込み |
| `clock` | 現在時刻の取得 |
| `random` | 乱数の取得 |
| `env` | 環境変数の読み込み |

未知の権限名は `BX072`。

**静的な伝播規則（check）**

- 標準の箱の権限は、宣言されたものがそのまま権限になる（一覧は [std.md](std.md)）
- 普通の箱は、本体で `call` しているすべての箱の権限の和集合を、自分の `perm` に**すべて宣言していなければならない**（不足は `BX071`）
- 宣言しているのに使っていない権限は警告 `BX073`
- これにより、人間は箱の外側を見るだけで、その箱（と中に入れ子になった箱すべて）が外に何をし得るかが分かる

**実行時の強制（run / trace）**

作用はすべて `boxundle` 自身が実装した標準の箱の中でしか起きないので、実行時に確実に強制できる。

- 実行する人は `--allow clock,net` のように、許可する権限を明示する。既定は何も許可しない
- 実行開始前に、実行する箱の `perm` が許可の範囲に収まっているかを確認し、収まっていなければ実行せずに `BX-RUN-020`（不足している権限を列挙）
- 作用のある標準の箱の実装は、呼ばれるたびに許可を確認する（二重の防御。違反は `BX-RUN-020`）
- ファイルの箱は、`--fs-root DIR`（既定はカレントディレクトリ）の外に出られない。Go の `os.Root` を使って、`..` やシンボリックリンクによる脱出を防ぐ。外を指したら `BX-RUN-021`

## 5. 検証（`check`）の内容

`check` は次の順で行い、見つかったエラーをすべて返す（最初の1つで止めない。ただし構文エラーがあればそこで止める）。

1. 標準の箱の宣言の読み込み（バイナリに埋め込まれたもの。読み込みに失敗したら内部の不具合）
2. モジュールの構文解析
3. 型定義の検証（未定義の型、循環、ユニオンに名前付きレコード以外、`std` で始まる名前）
4. 箱ごとに：
   1. ID規則（§4.2の1〜3）
   2. スコープ（§4.2の4〜6）
   3. 演算名・引数の数・束縛子・ブロックの形
   4. 型検査（各ノードの型を前から順に決める）
   5. 分岐の種類と網羅性
   6. 出力の網羅性（§4.4）
   7. テストの値とスタブが、ポートの型に合っているか
5. 箱の呼び出しグラフの循環検出
6. 権限の伝播（`BX071`、`BX073`）

型検査は前方参照がないため、ノードをテキスト順に1回走査すれば決まる。束縛子の型は、集まりの要素型（`fold` の `$acc` は `init` の型）から決める。

## 6. エラー形式

### 6.1 構造

すべての診断は次の形を持つ。`--json` 指定時はこのJSONの配列を標準出力に出す。指定しないときは人間向けに整形して標準エラー出力に出す。

```json
{
  "code": "BX022",
  "severity": "error",
  "message": "レコード型 Line にフィールド prodcut はありません",
  "box": "B7",
  "node": "#1.1",
  "path": "$e.prodcut",
  "span": {"file": "order.bx", "start": {"line": 14, "col": 28}, "end": {"line": 14, "col": 38}},
  "hint": "フィールド名の綴りを確認してください",
  "suggestions": ["product"]
}
```

- **主たる位置は `box` と `node`**（行という概念を持たない原則のため）。`span` は表示用の補助。`col` はコードポイント単位で1始まり
- 該当しない項目は省略する（`null` を出さない）
- `suggestions` は、修正候補があれば必ず入れる（名前の誤りなら編集距離2以内の候補。箱名の誤りなら標準の箱も候補に含める。演算名の誤りなら演算名の候補）
- `severity` は `error` か `warning`。`warning` は `BX073` だけ
- `--json` の配列は、診断が無ければ `[]`

人間向けの形（`--json` なし。標準エラー出力）：

```
エラー BX022  箱 B7  ノード #1.1  $e.prodcut
  レコード型 Line にフィールド prodcut はありません
  位置: order.bx:14:28
  ヒント: フィールド名の綴りを確認してください
  候補: product

エラー BX-RUN-020
  許可されていない権限が必要です: clock
  ヒント: --allow clock で許可してください
```

- 1行目は、重さ（`エラー` / `警告`）・コード・`箱 名前`・`ノード ID`・パスを、空白2つで区切って並べる。無い項目は書かない
- 2行目から下は2字下げで、`message`（複数行なら各行を2字下げ）・`位置: ファイル:行:列`（`span` の始まり）・`ヒント:`・`候補:`（`, ` で区切る）の順。無い項目の行は出さない
- 診断と診断の間は空行1つ

## 7. 値の受け渡し

### 7.1 JSON

型に導かれて変換する（同じJSONでも、期待される型によって解釈が決まる）。

| 型 | JSON |
|---|---|
| Int | 整数（任意の桁数。入力は小数点・指数を含まないこと） |
| Dec | 入力は数値または文字列、出力は常に文字列（例：`"12.50"`。指数表記を使わない） |
| Bool | 真偽値 |
| Str | 文字列 |
| [T] | 配列 |
| {Str -> V} | オブジェクト（出力はキー昇順） |
| {Int -> V} / {Bool -> V} | `[[キー, 値], ...]` の配列（出力はキー昇順） |
| レコード | オブジェクト |
| 名前付きレコード | オブジェクト。出力時は `"$tag": "型名"` を必ず含める。入力時は、ユニオン型の位置でのみ `"$tag"` 必須 |

- JSONの数値は `json.Decoder.UseNumber` で読み、精度を落とさない
- `run` の入力は `{"ポート名": 値, ...}`、出力も同じ形（キーはポート名の昇順）。ポートの過不足はエラー（`BX040` と同じ形式で、`node` なし）
- スタブのJSON（`--stubs`）は `{"箱の名前": {"出力ポート名": 値, ...}, ...}`
